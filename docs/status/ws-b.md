## Sun 11 Oct (Day 10), later: skills, router and follow-ups
- **Done (branch `ws-b/skills-router`, from `main`):** T5 and T6. **Skills:** `brain/skills/` holds the four `SKILL.md` files (`status-and-blockers`, `incident-investigation`, `design-discussion-summary`, `audit-inquiry`); a loader validates each (unknown source, tool or key, wrong schema, `max_evidence` out of range, empty procedure are refused), freezes it and pins it with a SHA-256 over its folder. A trigger-word router picks the skill (scenario 1 gets `status-and-blockers`, CTO question 1 `incident-investigation`, CTO question 2 `design-discussion-summary`; the breach question gets none). A skill narrows the sources searched, sets how much evidence goes to the model and adds its procedure to the model's system prompt (ADP's `SystemRole` and the OpenAI-style system message); it changes nothing in the policy plane. The audit event pins `skill`, `skill_version`, `skill_sha256`. `audit-inquiry` is for the audit agent and the compliance role only. **Follow-ups:** a new `understand` node after `identity` reads the earlier turns of the caller's own conversation, keeps only answered turns the person may still open (the existing label check plus a live PDP check, so a revoked source drops the turn), and rewrites a follow-up ("the second blocker?", "why?", "what about Dana?") into a standalone search query using the last turn's topic. A question with a subject of its own is left alone, so a new topic is not dragged back. The model gets the original question plus the turns as `history`, which is never evidence. Someone else's or an unknown conversation gives no memory and looks the same.

## Sun 11 Oct (Day 10): the audit agent
- **Done (branch `ws-b/audit-agent`):** T9 and fix F14. `POST /v1/audit/ask` (and the MCP `audit_query` tool when it gets only a `question`) turns a question in words into a plan: `query` (filter the log by person, space, document, decision, time window), `time_travel`, or `verify`. The plan is checked by `validate_plan` (unknown keys, people, spaces, documents, decisions and unreadable times are refused), then run by the same code the structured queries use, under the compliance role, and the summary is written by code. A question it cannot plan comes back as a clarifying question. Every question is logged once with its plan. A bare space name (`PAY`) now works (F14), and a new `doc` filter finds denied attempts on a document through the salted hashes.
- **Added later the same day:** refused questions count as denied attempts (a `denied` filter matches them; a `doc` filter matches refused questions that share two words with the document's title), and an optional model planner as a second chance when the rules cannot read a question (`AUDIT_PLANNER_*` settings; the model never sees a document title or an audit event; it names a document as a phrase that code resolves). The model path is tested against a fake endpoint only: no key yet, never run live.
